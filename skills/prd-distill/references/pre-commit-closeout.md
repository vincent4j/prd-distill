# 提交前收尾

当用户要求提交、保存并提交、推送，或 agent 准备运行 `git commit` 时，必须在提交前执行 PRD Distill 收尾。

## 与开发自测的边界

提交前收尾不是默认的合同测试阶段。合同覆盖应在功能开发完成后的自测环节完成；提交前只确认这些自测证据是否存在、是否仍然适用于当前 diff，以及 PRD / 合同 / inbox 是否需要收口。

- 如果开发自测已经覆盖受影响合同，提交前复用证据，不重复跑。
- 只有没有可追溯自测证据、自测后又改了受影响代码、合同/PRD 发生实质变化，或用户明确要求提交前完整验证时，才在提交前补跑相关测试。
- 可追溯证据不强依赖 worklog：最终回复里的合同 ID、测试命令、结果摘要和证据路径即可作为最低证据；有日志、截图、接口响应或大文件证据时，先落盘到 `/tmp/<project>-*` 并在回复里给路径。只有项目已有且本轮正在使用 worklog / plans / memory 时，才同步写入这些记录。

## 受影响事实面

提交前只核对本轮 diff 影响的事实面，不机械审计整个工作区。按需检查：

- 当前实现：代码、schema、配置或接口现在真正实现了什么。
- 运行证据：测试、API、日志、截图、DOM 或页面检查是否仍支持当前结论。
- 模块 PRD：当前有效行为、边界和验收标准是否需要更新。
- 约束合同：生效合同是否受影响，成熟的新约束是否需要进入草稿或生效合同。
- 入口桥接：仅检查 PRD Distill 受控块是否仍指向正确的 PRD / 合同入口。
- 历史输入：仅在本轮已经使用 plans / worklogs / memory 时判断是否需要提炼，不把它们当生效真相源。

每个适用事实面标记为 `无需修改 / 已更新并验证 / 待处理 / 范围外 / 不适用`。小改动不必强凑全部事实面；无法验证的结论必须标为 `待处理`，不能写成完成。

对每条受影响事实按 `当前实现或运行证据 -> 可能过期的 PRD / 合同 / 入口 -> 本轮处理 -> 验证` 路由。`scripts/prd_distill.py check` 通过只表示结构门禁通过，不能替代这项语义判断。

## 步骤

1. 先用 `git diff --name-only` 和 `git diff --stat` 确认本轮变更范围，提取受影响模块、字段、接口和行为词。
2. 运行 `scripts/prd_distill.py scan --root <repo>`，检查待处理的 PRD / 合同 inbox 草稿。
3. `scan` 只用于发现候选输入。scan 后必须按模块名、文件名、合同 ID 或当前变更路径收窄读取范围；不能因为 scan 发现 plans / worklogs / memory 存在，就全文读取这些文件。
4. 按受影响事实面判断哪些现役说法可能过期；如果存在需求碎片、强约束，或会影响 PRD 的实现变更，运行对应动作：
   - 用提炼 PRD 处理模块行为、工作流、字段、验收标准和决策变化。
   - 用整理约束合同处理已经在自测中有测试或运行证据支撑、且需要长期保留的硬约束。
   - 在最后一次提交前使用检查实现与文档是否一致。
5. 检查本轮自测证据是否覆盖受影响合同；如果证据缺失或自测后又改了相关代码，只补跑受影响合同对应的测试，不做全量合同重测。
6. 如果 PRD 结构或入口桥接受本轮影响，只检查并更新 PRD Distill 受控块，不重写项目通用规则。
7. 将生成或更新的 PRD / 合同文件和代码变更一起 stage。
8. 只提交一次，让代码和 PRD / 合同收尾进入同一个 commit。

## context-keeper 输入

如果本轮会话刚运行过 `context-keeper`，或当前变更里出现新的 `docs/plans/`、`docs/worklog/`、`docs/memory-keeper.md`，并且用户要求提交、保存并提交或推送，必须把这些文件视为 PRD Distill 输入：

- 先用本轮模块名、触发词、文件名和合同候选检索。
- 只读取相关命中内容。
- 判断是否需要进入 PRD / 合同草稿或生效合同。
- 不要让 plans / worklog / memory 单独提交而未检查是否需要提炼到 `docs/prd/`。

## 收尾汇报

最终只列适用事实面，并明确仍未闭环的内容：

```text
收尾状态：
- 当前实现：<无需修改 / 已更新并验证 / 待处理；证据>
- 运行证据：<无需修改 / 已更新并验证 / 待处理；证据>
- 模块 PRD：<无需修改 / 已更新并验证 / 待处理；文件>
- 约束合同：<无需修改 / 已更新并验证 / 待处理；合同 ID 或草稿>
- 入口桥接：<无需修改 / 已更新并验证 / 不适用>
- 历史输入：<不适用 / 已更新并验证 / 待处理；来源>
- 待处理 / 范围外：<没有则写“无”>
```

没有生效合同命中时不输出合同验收矩阵，但仍报告其他适用事实面，避免把“无合同”或 `check` 通过误报为全部收尾完成。

## 提交时机

- 不要等 `git commit` hook 失败后才开始 PRD 收尾。
- 成功提交后不要再生成 PRD 或合同文件。
- 如果提交后、推送前才发现缺文档，优先 amend 同一个 commit。
- 如果已经推送，只有在用户明确同意时才创建后续提交。
- Claude Code 全局 hooks 可能会在存在 PRD / 合同草稿时阻止 `git commit`。把这个阻止视为最后兜底：在同一个 agent 回合里继续运行本 skill 收尾、stage 生成的文档，并自动重试 `git commit`。
