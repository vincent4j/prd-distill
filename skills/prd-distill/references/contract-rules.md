# 约束合同规则

把合同视为 PRD 的可执行约束层，而不是独立系统。

## 何时写合同

当用户给出强约束时，先写草稿合同：

```text
必须 / 不能 / 每个 / 一定 / 不能靠猜 / 之前解决过又复现 / 为什么会没有
```

只有满足至少一个条件时，才提升为生效合同：

- 根因已经确认。
- 行为足够稳定，可以成为长期规则。
- 回归代价高或风险高。

没有测试或运行证据时，不要创建生效合同，只能标记为草稿。

## 生效合同字段

生效合同必须包含：

- ID 和标题
- 类型：field、decision、runtime、quality、safety、API 或 UX
- 关联 PRD 章节
- 要求
- 相关字段/来源合同
- 失败处理
- 测试绑定
- 运行/日志证据
- 触发范围
- 状态

使用 `scripts/prd_distill.py new-contract ...` 创建草稿合同。

## 整理约束合同流程

1. 检查用户消息、`docs/prd/inbox/`、近期 plans / worklogs / memory 的合同候选和已有合同中的强约束。
2. 优先检索模块名、触发词、错误现象、字段名、接口名或合同 ID，只读命中条目和相邻上下文。
3. 当约束仍不稳定时，创建草稿合同，不要直接提升为生效合同。
4. 只有当要求、失败处理、测试绑定、运行/日志证据和触发范围都清楚时，才提升为生效模块合同。
5. 优先使用模块级合同文档，例如 `docs/prd/contracts/<module>.md`，不要按类型创建全局合同文件。
